# Чураков Н.М. Команда исследования технологий машинного обучения

## Результат

Подготовлена система инференса Qwen2.5-1.5B-Instruct BF16 через vLLM 0.32.0 на CPU в Minikube. Выполнены основные требования и три дополнительных задания. Код, конфигурация и подтверждения размещены в [репозитории](https://github.com/AlbinoTugboat/safeboard-vllm-cpu).

## Реализация

| Требование | Реализация |
|---|---|
| Kubernetes и только CPU | Kubernetes 1.36.5 в Minikube, CPU-колёса PyTorch, GPU не подключаются |
| Собственный непривилегированный образ | Многоэтапный Dockerfile, UID/GID 10001, read-only root filesystem, capabilities сброшены |
| Зависимости | Прямые и транзитивные Python-зависимости закреплены версиями и хешами; базовые образы закреплены digest |
| Приватность | Форматтер метаданных, ASGI middleware и Python exception hooks; факт обращения сохраняется без prompt и ответа в проверенных путях |
| Модель и PVC | InitContainer скачивает точный commit, проверяет SHA-256 и повторно использует кэш; inference читает отдельную проверенную копию |
| Secret | HF token и Bearer token передаются отдельными ключами, каждому контейнеру доступен нужный ключ |
| ConfigMap | Параметры запуска и CPU вынесены в файлы, изменение ConfigMap обновляет Pod без пересборки |
| Инструкция | [README.md](README.md), `scripts/deploy.ps1`, клиент и проверочные скрипты |

Дополнительные задания: Kustomize (`kubectl apply -k`), отдельный непривилегированный образ загрузчика и нагрузочное тестирование коротких/длинных запросов с анализом настроек.

## Ресурсы и выбранные настройки

Кластер: 12 логических CPU и 16 ГиБ RAM. Основной контейнер: лимит 10 CPU / 12 ГиБ, PVC 10 ГиБ, отдельное временное хранилище для проверенной копии весов около 3,1 ГБ. Модель и ревизия `989aa7980e4cf806f80c7fef2b1adb7bc71aa306` сохранены.

После сравнения выбраны OMP/MKL 7, привязка `auto`, бюджет батча 1024. Контекст 4096, KV-кэш 2 ГиБ. Увеличение бюджета батча до 2048 не прошло порог общего выигрыша. Настройки подобраны для этой машины; на другом CPU требуется проверка.

Данные от 23 октября относятся к финальному образу после исправлений безопасности. Сравнение A–B–B–A, по 24 запроса на сценарий и вариант, 64 выходных токена. Прогрев исключён; входы одинаковы, cache_salt уникален. Задержки — среднее / p95, в секундах.

## Проверки

51/51 тест в Linux без сети и с непривилегированным пользователем; на Windows прошли 40, 11 POSIX-проверок выполнены в Linux. Оба образа собраны. Ранее 23 октября проверены реальная первая загрузка в новый пустой PVC и повторный запуск с кэшем; образы и модель после этого не менялись.

24 октября выполнена полная 20-минутная смешанная проверка: 290 запросов, ошибок 0, вход до 3752 токенов, выход 64–256 токенов, четыре клиента. Готовность сервиса сохранилась; OOM и перезапусков в ходе теста не было. Авторизация и приватность логов проверены до и после нагрузки. Максимум памяти среди замеров — 8,52 ГиБ; показатель включает файловый кэш. Прерванная попытка предыдущего дня исключена из этих итогов.

В 12 синтетических заданиях исходная и выбранная конфигурации прошли 9 и 9 проверок соответственно; ранее проходившие задания сохранены. Это не оценка общей точности модели.

## Ограничения

Решение предназначено для локального доступа через loopback port-forward. Внешняя публикация требует TLS и ограничений доступа и нагрузки. Двадцать минут тестирования не исключают медленные утечки памяти или сбои за часы и дни; нагрузка закрытая и не моделирует произвольную интенсивность входящего потока.

При восстановлении кластера до нагрузки один старт inference завершился с кодом 1, повторный запуск восстановил готовность; причину установить не удалось. Плановый перезапуск после нагрузки прошёл с тем же PVC, проверкой кэша и без автоматических рестартов нового контейнера. Дополнительная остановка и запуск Minikube прошли без лишних попыток старта; исходный сбой не воспроизвёлся. Подробности — в результатах новой серии.

Сохраняются замечания сканера к setuptools, его встроенным jaraco.context/wheel и пакетам ОС. Их совместимое обновление требует согласованного перехода vLLM. Связанные сценарии установки и распаковки архивов штатным offline inference не вызываются. Подробности — [results/security-fixes.md](results/security-fixes.md).

Репозитории apt изменяемы; побитовая воспроизводимость сборки не заявляется. Механизм Python logging/exception hooks не фильтрует произвольный native/raw stdout. Частная копия модели увеличивает время запуска и расход файлового кэша памяти.

## Запуск

В PowerShell из корня проекта: `./scripts/deploy.ps1`. Затем выполнить port-forward и запросы по инструкции README. Веса и секреты не входят в репозиторий; ключи создаются локально. Точная ревизия и хеши весов заданы в `model.lock.json`.
