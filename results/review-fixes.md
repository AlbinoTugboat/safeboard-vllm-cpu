**Исправления после независимого ревью — 21 октября 2026 года**

Все пять замечаний R1–R5 из ревью закрыты.

| Замечание | Исправление | Подтверждение |
|---|---|---|
| R1, P2: Bearer token при redirect | Общий API-клиент запрещает HTTP redirects | Локальные серверы и синтетический токен: 301/302/303/307/308 завершаются ошибкой, принимающий сервер не получает запросов |
| R2, P2: Secret в другом кластере | Создание Secret имеет явный `--context`; deploy передаёт `safeboard` | Тесты создания/сохранения Secret; реальный deploy успешен с `KUBE_CONTEXT=review-should-not-be-used` |
| R3, P2: локальный хеш объявлен серверным | Поле переименовано в `local_config_sha256`; опциональная проверка `--kube-context` связывает endpoint с Pod и его ConfigMap до/после серии | Новый реальный benchmark: `kubernetes_evidence.status=pod_verified`; снимки совпали; тесты отказа при несовпадении настроек, смене Pod и чужом request ID |
| R4, P3: загрузка перед гарантированным отказом кэша | Повреждённый финальный кэш отвергается до импорта Hub; отдельная безопасная причина `existing_cache_invalid` | Повторные попытки не вызывают Hub и не создают partial; добавлена инструкция восстановления |
| R5, P3: хеш зависит от CRLF/LF | Manifest хешируется как канонический JSON; алгоритм явно записан в отчёте | Проверка одинакового хеша после переформатирования JSON; сравнение с `environment.json` |

Дополнительно Secret проецируется раздельно: downloader получает только `hf-token`, inference — только `api-token`. При повторном deploy уже работающий здоровый профиль Minikube используется без повторного запуска. Ветвь проверена с подменой внешних команд; создание/запуск отсутствующего профиля не менялись.

Повторная узкая проверка теми же тремя субагентами подтвердила закрытие замечаний безопасности, качества и доказательности результатов. После обнаруженного ими сброса TCP в Windows-fixture тестовый сервер исправлен: читает тело POST и корректно оформляет пустой ответ. Основной агент повторил проверки на Windows и Linux.

Подтверждённые результаты:

- Linux: 26 из 26 тестов прошли в non-root downloader-образе, с отключённой сетью, read-only filesystem и отдельным `/tmp`.
- Windows: 20 тестов прошли; 6 POSIX-тестов downloader выполняются в Linux.
- Оба образа собраны; downloader обновлён до тега `1.2`.
- Обновлённый Deployment готов, контейнер работает с UID 10001, vLLM 0.32.0 и PyTorch 2.13.0+cpu; CUDA отсутствует.
- Проверка авторизации, генерации, audit-записей и отсутствия приватного содержимого в логах прошла.
- Офлайн-проверка действительного PVC прошла; init-контейнер при реальном обновлении сообщил `model_cache_hit`.
- Новый benchmark выполнен: 32 измеряемых запроса, четыре сценария по 8, по 32 выходных токена; ошибки отсутствуют. Raw-измерения и проверка Pod находятся в `benchmark.json`, таблица — в `benchmark.md` и README.

Данные тестов сохранены в `tests.json`, сведения об окружении — в `environment.json`, проверки endpoint и кэша — в `verification.json` и `offline-cache.json`.

Проверка загрузки и возобновления в unit tests использует stub HF и настоящий POSIX `fcntl`; повторной передачи 3,1 ГБ с HF в этом этапе не выполнялось. Реальный deploy проверен с существующим PVC. Полный запуск с пустым PVC в отдельной среде остаётся отдельной проверкой воспроизводимости. Kubernetes evidence подтверждает спецификацию Pod и ConfigMap; внутренние параметры процесса отдельно не опрашиваются.
