# Исправления безопасности — 23 октября 2026 года

Исправления сделаны после security audit от 23 октября. Модель BF16, версия vLLM 0.32.0, зависимости приложения и параметры CPU/генерации сохранены.

## Закрытые проблемы

| Проблема | Изменение | Проверка |
|---|---|---|
| S1: токен и prompt могли уйти ambient HTTP proxy | Общий клиент явно отключает proxy; внешний HTTP запрещён, для внешнего endpoint нужен HTTPS; redirects по-прежнему запрещены | Локальный proxy-listener не получил ни одного запроса, direct listener получил запрос; unsafe URL отвергаются до сетевого вызова |
| S2: дополнительные файлы могли влиять на loader | Проверка допускает только manifest-файлы и инертные Hub metadata; symlink каталогов/файлов и некорректный partial отвергаются | Regression tests для дополнительных index/весов/template, symlink и отказа до Hub/network |
| S2: общий PVC мог измениться после init | Launcher копирует и хеширует фактически копируемые bytes в отдельный inference-only emptyDir; vLLM читает только эту копию | Проверены изменение PVC после копирования, повреждение перед копированием, точный набор файлов и повторный старт без накопления копий |
| S3: старый базовый pip и его vendor/CA payload | Из обоих runtime-образов удалены base pip, wrappers и ensurepip; сборка продолжает использовать pinned uv | Повторный Trivy scan и проверка отсутствия модулей в реальном контейнере |
| Дополнительно: слабая очистка исключений cleanup | Добавлен безопасный unraisable hook | Synthetic destructor и atexit ошибки не выводят приватный маркер |
| Дополнительно: context проверки мог расходиться | verify_endpoint принимает один явный context для токена и logs | Реальная проверка выполняется с посторонним KUBE_CONTEXT при явном safeboard |
| Дополнительно: изменяемый Docker frontend | Dockerfile frontend закреплён точным digest | Оба Dockerfile успешно собраны с этим digest |

При проверке после рестарта обнаружен сброс локального port-forward на раннем отказе в неавторизованном POST. Middleware теперь отбрасывает короткие неавторизованные тела с пределом 32 КиБ / 0,25 с, не буферизуя их и не выводя в журнал. Проверяющий скрипт ограниченно читает и закрывает HTTP error response. Для авторизованных запросов сохраняется прежняя streaming-семантика без чтения тела middleware. Неограниченное вычитывание больших или медленных тел не добавлялось.

## Цена защиты кэша и граница доверия

Нужен отдельный дисковый emptyDir до 4 ГиБ; текущая модель занимает 3 098 955 668 байт. Он монтируется только в inference, а не в init/downloader. Каждый старт inference создаёт проверенную копию и удаляет свою предыдущую плоскую копию, если контейнер перезапустился в том же Pod. Добавляются локальное чтение/копирование и проверка SHA при старте, сетевого скачивания нет. Настройки генерации не менялись, новая оценка throughput не проводилась.

Копирование также использует файловый кэш Linux, учитываемый в памяти контейнера. Он может освобождаться ядром при давлении на память; это не только дополнительный диск без какого-либо эффекта на память. В коротких проверках с реальной моделью превышения memory limit/OOM не наблюдались; пределы CPU/RAM не увеличивались. Это не новый длительный стресс-тест.

Это защищает модель от изменения общего PVC после проверки. Писатель может повредить PVC и вызвать отказ будущего запуска; обеспечение доступности при таком доступе в задачу не входит. Доступ к самому inference-контейнеру, его приватному emptyDir или доверенной конфигурации остаётся отдельной, более сильной границей.

## Оставшиеся ограничения

В inference остаются `setuptools==78.1.1` и его vendored jaraco.context/wheel: точный CPU wheel vLLM 0.32.0 требует этот pin. Их нельзя безопасно заменить одиночным bump без согласованного обновления upstream. Связанные archive/sdist/installer сценарии не вызываются штатным offline inference; статус не обозначен как «все CVE исправлены».

После удаления base pip сканер не находит Python CVE в downloader; в inference остаются три совпадения setuptools/vendor. Совпадения CVE пакетов ОС сохранены в raw scan и не скрыты ignorelist. Большая группа относится к заголовкам ядра и build tooling; она не является доказательством remote эксплуатации API. Текущие apt repositories остаются изменяемым входом сборки.

Механизм logging/hook не фильтрует произвольный native/raw stdout. Не выполнялись публичный pentest, разрушительные CVE/DoS проверки или новый длительный benchmark. Исторические benchmark и снимок environment за 21 октября сохранены без подмены новыми Pod/image ID. Актуальные результаты тестов — `tests.json`, проверки новой модели и рестарта — `security-fixes.json`.

## Проверки

- Linux: 48 из 48 тестов, отключённая сеть, UID 10001, read-only filesystem и tmpfs.
- Windows: 37 прошли, 11 POSIX downloader/symlink тестов выполняются в Linux.
- Сборка обоих образов: успешно. Downloader обновлён до `1.3`.
- Реальная модель: API, авторизация, audit и отсутствие приватного содержимого в логах прошли до и после намеренного SIGTERM inference. UID Pod сохранён, restart count увеличился ровно на один; проверенная копия заменена в том же emptyDir.
- Новый downloader прошёл отдельную проверку настоящего PVC с `HF_HUB_OFFLINE=1`; init использовал hash-verified cache без нового скачивания.
- Raw данные повторного image scan и журналы тестов находятся в рабочем каталоге `work/security-fixes-2026-10-23` вне репозитория; машинная сводка проверки сервиса сохраняется в `security-fixes.json`.

Секреты и тексты ответов модели в результаты не сохраняются. Runtime-проверка выше использует существующий PVC. При финализации 23 октября первая реальная загрузка финальных образов дополнительно проверена в новом профиле Minikube с пустым PVC; после пересоздания Pod подтверждён кэш без скачивания. Итоговая сводка — [final-acceptance.json](final-acceptance.json).
